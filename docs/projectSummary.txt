Cazzijobz Project Summary
📱 App Overview
Name: cazzijobz (Casual Jobs)
Mission: Community-driven platform connecting people offering casual labor (Workers) with those needing tasks done (Employers)
Target Audience: Lower-income communities worldwide for casual work (gardening, cleaning, construction, domestic work, etc.)
Location: South Africa focused, globally scalable
Monetization: Google AdMob (future implementation)

🛠 Tech Stack
Frontend: React Native + Expo

Backend: Supabase (Auth, Database, Storage)

State Management: React Context + AsyncStorage

Navigation: React Navigation

IDE: VS Code

Testing: Windows 10 + Android USB

🏗 Architecture Foundation
API Call Strategy
Type A (Immediate): Critical actions that need instant server sync

Signup, Login, Initial Profile Completion

Job posting, Job applications, Hiring decisions

Type B (Debounced): Non-critical updates that can be batched

Profile updates (name, bio, location, profile_pic)

Preference changes

Status updates

Timing Configuration:

Development: 1-minute timeout between Type B calls

Production: 5-minute timeout between Type B calls

Location: src/hooks/useProfileSync.js constants

AsyncStorage Strategy
Latest Data Wins: Subsequent changes overwrite previous pending changes

Automatic Retry: Failed syncs remain in storage for retry

Cross-session Persistence: Pending changes survive logout/login cycles

Storage Keys: userProfile, pending_profile_changes, last_api_call, isAdmin, authToken

🔄 Smart Profile Synchronization System
Core Implementation
File: src/screens/shared/profile/ProfileScreen.js

Immediate Local Save: User changes saved to AsyncStorage instantly

Timeout-based Sync: Type B calls debounced with configurable timeout

Pending Changes Management: Unsynced changes preserved across sessions

Smart Merge Logic: Local changes merged with server data on login

Key Behavior
User edits profile → Save to local storage immediately

Check timeout status:

Outside timeout (>1min): Make Type B API call immediately

Within timeout (<1min): Batch changes locally, sync later

Logout/Login: Pending changes preserved and merged

Error Handling: Failed syncs remain in queue for retry
